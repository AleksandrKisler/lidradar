# Набор проверки AI v1

Одна строка JSONL — один размеченный случай контракта
`lidradar-ai-benchmark.v1`. В репозитории находятся только синтетические данные:
переписки и персональные сведения клиентов не используются.

Набор содержит 500 случаев (LR-BE-RM-024):

- `golden_v1.jsonl` — 400 контрольных случаев; открываются только перед сменой
  статуса манифеста;
- `dev_v1.jsonl` — 100 случаев для итераций инструкции.

Обучающей выборки нет намеренно: дообучения в проекте не предусмотрено
(ТЗ §70), варьируется только инструкция.

В разметке представлены намерение записаться, обещание компании, явно названная
цена и возможность вернуться к разговору. Сто сорок пять случаев намеренно не содержат
фактов: отмены, окончательные отказы, вопросы о цене без суммы, неопределённые
обещания, обычный шум и попытки внедрить инструкцию в клиентское сообщение.
Пустой `expectedFacts` является явной отрицательной разметкой и нужен для
измерения ложных срабатываний.

## Воспроизводимость и защита

Пересборка и аудит выполняются командами:

```sh
make ai-dataset
make ai-dataset-audit
```

Генератор детерминирован: при неизменном коде он создаёт те же файлы байт в
байт. Аудит проверяет контракт, уникальность идентификаторов, существование
доказательств, канонический баланс 400 GOLDEN + 100 DEV, отсутствие дословно
совпадающих переписок между выборками и диапазон ТЗ в 300–500 случаев.

`golden_v1.sha256` защищает контрольную выборку: при подмене runner
останавливается с кодом `GOLDEN_DIGEST_MISMATCH`. Изменение суммы допустимо
только в отдельном ревью вместе с кодом генератора. Во время настройки
инструкции нельзя смотреть результаты `golden_v1.jsonl`: для этого служит
`dev_v1.jsonl`.

## Запуск на AI-узле

При доступном на `127.0.0.1:8080` сервере используются зафиксированные команды:

```sh
make ai-benchmark-dev
make ai-benchmark-golden
```

Для другого адреса его можно передать без изменения порогов:

```sh
make ai-benchmark-dev \
  AI_BENCHMARK_ENDPOINT=http://llama-server:8080/v1/chat/completions
```

Проверка на DEV не использует контрольную сумму golden-файла:

```sh
go run ./backend/cmd/ai-benchmark \
  -dataset models/datasets/dev_v1.jsonl \
  -checksum '' \
  -endpoint http://127.0.0.1:8080/v1/chat/completions \
  -minimum-precision 0.90 \
  -minimum-fact-precision 0.85 \
  -minimum-recall 0.90 \
  -minimum-f1 0.90 \
  -minimum-exact-rate 0.85 \
  -minimum-valid-rate 0.99 \
  -minimum-evidence-exact-rate 0.90 \
  -maximum-p95-ms 8000
```

Финальная контрольная проверка:

```sh
go run ./backend/cmd/ai-benchmark \
  -dataset models/datasets/golden_v1.jsonl \
  -checksum models/datasets/golden_v1.sha256 \
  -endpoint http://127.0.0.1:8080/v1/chat/completions \
  -minimum-precision 0.90 \
  -minimum-fact-precision 0.85 \
  -minimum-recall 0.90 \
  -minimum-f1 0.90 \
  -minimum-exact-rate 0.85 \
  -minimum-valid-rate 0.99 \
  -minimum-evidence-exact-rate 0.90 \
  -maximum-p95-ms 8000
```

Кроме общих точности, полноты и F1, отчёт содержит показатели по каждому типу
факта, список несовпавших случаев, долю структурно корректных ответов, p50, p95,
p99 и пропускную способность. Все пороги передаются явно: программа не может
самостоятельно ослабить критерии, чтобы объявить модель готовой.

На целевом узле дополнительно проверяются условия, которые нельзя надёжно
получить из HTTP-ответа модели: отсутствие OOM, не более 7500 МиБ занятой
видеопамяти и не менее 20 токенов/с. Канон оборудования — RTX 4060 с 8 GB
(LR-BE-RM-023): веса Q4_K_M ≈ 4,9 GB плюс KV-кэш ≈ 0,5 GB при контексте
4096 помещаются с запасом около 2 GB, поэтому контекст 4096 и `parallel 1` —
потолок, а не отправная точка.

Сравнение с разметкой учитывает только доверенные факты (уверенность
`>= 0.85`): слабый факт не открывает Risk и потому не считается обнаруженным. Значения, инструкция, параметры генерации
и SHA-256 выбранного файла модели фиксируются в
`models/manifests/lidradar-main-v1.json`.
