# LidRadar — макеты для ручного импорта в Figma

Версия 0.2 · 3 сентября 2026 года.

В комплекте 16 векторных листов: 14 экранов для компьютера, лист состояний и основы оформления. Они продолжают визуальный язык открытого файла «LidRadar — Product UI v0.1»: Inter, тёмное боковое меню, светлая рабочая область, фиолетовое основное действие и спокойные цветовые обозначения рисков.

Существующий файл Figma не изменялся. Для создания этого комплекта обращения к Figma MCP не использовались. Имена, цены, даты, оплаты, состав команды и состояния подключений в макетах — демонстрационные, не результаты проверки работающей системы. Настоящие пароли, токены и содержимое `.env` не использовались.

## Быстрый просмотр

Откройте `index.html` двойным нажатием. Галерея работает без сервера и без интернета. В ней есть все экраны, переходы к разделам и ссылки на отдельные SVG. Папка `preview` содержит PNG для просмотра, а `overview.png` — общий обзор.

## Как импортировать

1. Распакуйте архив целиком.
2. Откройте существующий файл LidRadar в **Figma Design**, выберите нужную страницу и свободное место на холсте.
3. Перетащите один или несколько файлов из папки `svg` на холст. Импортируйте именно SVG, не PNG из папки `preview`.
4. Проверьте размер: обычный экран — 1440 × 1024, листы состояний и основ — 1440 × 1180. При необходимости верните исходный масштаб.
5. Проверьте текст. В исходных SVG сохранены настоящие элементы `<text>`, а не контуры букв. Используется Inter. Если Figma заменяет шрифт или сообщает о его отсутствии, установите комплектный `fonts/InterVariable.ttf` через «Шрифты» macOS и выберите Inter. Шрифт уже используется в исходном макете LidRadar.
6. Сохраните исходную группу как резервную копию. Для дальнейшей работы объедините логические блоки во фреймы и настройте автоматическую раскладку. Повторяющиеся кнопки, поля и навигацию после импорта можно превратить в компоненты Figma.

### Ограничения формата

SVG сохраняет векторные формы, цвета, координаты и исходный текст, но **не переносит нативную модель Figma**: автоматическую раскладку, связи компонентов, переменные, ограничения размеров и переходы прототипа. Импорт в вашу Figma намеренно не выполнялся, поэтому конкретное поведение её импортера не проверено. После импорта сопоставьте экран с PNG; если текст преобразуется или подменяется, оригинальная формулировка остаётся в SVG и в исходнике сборки.

Это не файл `.fig` и не полностью готовая библиотека компонентов. Папка `preview` — только изображения для сверки; редактируемый исходный материал находится в `svg` и `source`.

Справка Figma: [шрифты](https://help.figma.com/hc/en-us/articles/360039956894-Add-a-font-to-Figma), [текст и контуры в SVG](https://help.figma.com/hc/en-us/articles/13402894554519-Export-formats-and-settings-for-static-designs).

## Что учтено из требований

- Переписка показывается как контекст, а не как отдельная CRM-воронка. Самостоятельной отправки ответа клиенту из LidRadar в макетах нет.
- Источник сообщений Telegram и личные уведомления — независимые подключения.
- Для рабочей точки показаны все семь дней, её часовой пояс и стандартный порог ответа 45 минут. Выходной не равен рабочему интервалу с нулевой продолжительностью.
- Неизвестная цена остаётся неизвестной. Диапазон не превращается в произвольное среднее значение.
- «Оплатил» — результат контакта, не подтверждение выручки. Для денег показана отдельная операция с суммой, валютой и характером связи с риском.
- В возвращённую выручку входит только подтверждённая связь с риском, действием и результатом. Обычная оплата и неизвестная связь показаны отдельно.
- Владелец управляет настройками. Менеджер работает с рисками, диалогами, действиями, результатами и разрешёнными подтверждениями оплаты.
- Ошибка чтения не изображается как «0 рисков». Сохранённый снимок имеет время последнего обновления.
- При ограничении входа используется срок ожидания от сервера; ответы не должны выдавать, существует ли введённая почта.
- Секреты Telegram не показаны. Тихие часы не смешаны с рабочим графиком точки.

Подробные границы готовности и сценарии находятся в `SCENARIOS_RU.md`. Макеты описывают целевой интерфейс и **не доказывают наличие всех его API**. В частности, агрегированная аналитика и полные настройки уведомлений нуждаются в отдельной сверке реализации перед подключением фронтенда.

## Что ещё не входит

Мобильная версия, интерактивный прототип, регистрационная форма, выбор организации после входа, первоначальный ввод реквизитов источника Telegram, форма добавления/редактирования услуги, подтверждение отзыва доступа, все варианты закрытия риска и записи результата. Это следующий набор, а не скрыто «готовые» сценарии.

В исходном существующем макете найдено расхождение примера: у Дмитрия на Radar — полировка Audi A6, а в Risk Workspace — керамика BMW X5. Новые экраны используют полировку Audi A6 и 31 000 ₽. Старые экраны не изменены; их стоит привести к тому же примеру вручную.

## Исходники и проверка

- `source/build.mjs` — сборка макетов из общих элементов, без растра.
- `source/icons.json` — используемые векторы Lucide; лицензия рядом.
- `design-tokens.json` — цвета, размеры, отступы и шрифт.
- `source/verify.mjs` — измерение текста в браузере и создание PNG.
- `qa-report.json` — размеры, число текстовых элементов и результат проверки каждого файла.
- `fonts` — Inter и лицензия OFL. Шрифт не устанавливается автоматически.

Для повторной сборки достаточно Node.js:

```sh
node source/build.mjs
```

Для повторной проверки нужны Playwright, Sharp и Google Chrome. Укажите путь к папке с установленными пакетами:

```sh
LIDRADAR_NODE_MODULES=/путь/к/node_modules node source/verify.mjs
```

Проверка выполняется в отдельном временном профиле браузера. Она не читает пользовательские вкладки, пароли или историю. Скрипт не устанавливает пакеты и не обращается к Figma.
