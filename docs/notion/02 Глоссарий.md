# 02 Глоссарий

Термины сгруппированы по темам. В колонке «Значения» — точные
идентификаторы из кода и базы: так же они приходят в API и видны в
PostgreSQL.

## Организации и доступ

| Термин | Что это | Значения и правила |
|---|---|---|
| Организация (Organization, tenant) | Арендатор системы и граница всех данных; каждая бизнес-таблица несёт `tenant_id` | статусы `ACTIVE`, `SUSPENDED`, `ARCHIVED`; часовой пояс и валюта по умолчанию (`RUB`) |
| Членство (Membership) | Связь пользователя и организации с ролью; никогда не удаляется, только отзывается | роли `OWNER`, `MANAGER`; статусы `ACTIVE`, `INVITED`, `DISABLED` |
| Разрешение (Permission) | Именованное право, выдаваемое ролью; проверяется первым в каждом сценарии | 15 прав: `risks.read`, `risks.manage`, `conversation.read`, `opportunity.manage`, `action.manage`, `outcome.manage`, `revenue.confirm`, `revenue.read`, `analytics.read`, `integration.manage`, `organization.manage`, `location.manage`, `service.manage`, `notification.manage`, `member.manage` |
| OWNER | Владелец: все 15 разрешений | — |
| MANAGER | Менеджер: 7 рабочих разрешений | `risks.read`, `risks.manage`, `conversation.read`, `opportunity.manage`, `action.manage`, `outcome.manage`, `revenue.confirm` |
| Точка (Location) | Место обслуживания со своим часовым поясом, порогом ответа и часами работы | порог ответа 1…1440 мин, по умолчанию 45; расписание — ровно 7 дней |
| Часы работы (Business hours) | Недельное расписание точки; правила риска считают время только внутри него | `weekday` 1…7, `opens_at < closes_at`, закрытый день без границ |
| Рабочее время (Business time) | Способ измерять пороги: ночь и выходные не засчитываются | интервалы через полночь задаются двумя периодами соседних дней |
| Сессия (Session) | Непрозрачный серверный токен в cookie `lidradar_session` | хранится только SHA-256; срок 30 суток; `HttpOnly`, `SameSite=Strict`, `Secure` вне разработки |
| X-Tenant-ID | Заголовок выбора организации в запросе; задаёт и контекст RLS | UUID из `GET /api/v1/auth/me` |
| ML-согласие (ML consent) | Явное согласие организации на использование её данных в наборах | область `DATASETS`, одно действующее, история хранится |
| PLATFORM_ADMIN | Право платформенного администратора; строка в `platform_admins`, не членство | первая выдача — только CLI `platform-admin grant` |

## Каналы и переписки

| Термин | Что это | Значения и правила |
|---|---|---|
| Подключение канала (Channel connection) | Источник сообщений организации с секретом проверки вебхука и зашифрованными реквизитами | провайдеры `CONNECTED_BUSINESS_BOT`, `GENERIC_WEBHOOK`, `TEST`, `IMPORT`; статусы `ACTIVE`, `DEGRADED`, `ERROR`, `DISCONNECTED` |
| Способность (Capability) | Что канал умеет | `CAN_RECEIVE_MESSAGES`, `CAN_SEND_MESSAGES`, `CAN_IMPORT_HISTORY`, `CAN_RECEIVE_EDITS`, `CAN_RECEIVE_DELETES`, `CAN_RECEIVE_ATTACHMENTS`, `CAN_IDENTIFY_CONTACT` |
| Вебхук (Webhook) | Входящий запрос провайдера на `/api/v1/webhooks/{provider}/{tenant}/{connection}`, аутентифицируется секретом заголовка | `X-LidRadar-Webhook-Secret` или `X-Telegram-Bot-Api-Secret-Token`; ответ `202` |
| Сырое событие (RawEvent) | Событие провайдера, сохранённое как есть до интерпретации (persist-first) | статусы `RECEIVED`, `PROCESSING`, `PROCESSED`, `FAILED`; дедупликация по внешнему идентификатору |
| Persist-first | Принцип «сначала сохранить, потом разбирать»: провайдер получает ответ после записи сырого события | одна короткая транзакция на вебхук |
| Каноническое событие (CanonicalEvent) | Канало-независимое описание изменения переписки | `message.received.v1`, `message.edited.v1`, `message.deleted.v1`, служебное `connection.updated.v1` |
| Нормализация | Преобразование сырого события в канонические и применение к переписке фоновым заданием | `connector.normalize-raw-event.v1` |
| Контакт (Contact) | Клиент как его видит система: имя, телефон, почта; внешние личности привязаны к подключению | `external_identities` уникальны в паре с подключением |
| Переписка (Conversation) | Диалог контакта с бизнесом в одном подключении | статусы `ACTIVE`, `ARCHIVED`; поле `revision` растёт только при фактическом изменении |
| Сообщение (Message) | Единица переписки с направлением и типом | `INCOMING`, `OUTGOING`, `SYSTEM`; типы `TEXT`, `IMAGE`, `VIDEO`, `AUDIO`, `VOICE`, `DOCUMENT`, `OTHER`; удаление ставит `provider_deleted_at` |
| Вложение (Attachment) | Метаданные файла сообщения; двоичное содержимое пока не хранится | ключ объекта, MIME, размер, SHA-256 |
| Ревизия (Revision) | Счётчик изменений переписки; ключ дедупликации заданий и основа свежести AI | `conversation:{id}:revision:{n}` |

## Сделки и риски

| Термин | Что это | Значения и правила |
|---|---|---|
| Услуга каталога (Service) | Позиция каталога организации с точными ценами; упоминание услуги делает переписку коммерческим кандидатом | цены — десятичные строки, `priceFrom <= priceTo`, валюта из трёх букв |
| Кандидат (Commercial candidate) | Входящее текстовое сообщение, пословно упоминающее ровно одну активную услугу | неоднозначность — без сделки |
| Сделка (Opportunity) | Коммерческая возможность внутри переписки; не больше одной активной на переписку | этапы `NEW`, `ENGAGED`, `QUALIFYING`, `PRICE_SENT`, `WAITING_CUSTOMER`, `WAITING_BUSINESS`, `BOOKING_INTENT`, `BOOKED`, `WON`, `LOST`, `ARCHIVED` |
| Источник перехода (History source) | Кто перевёл сделку на этап | `RULE`, `AI` (с уверенностью), `USER` (с актором), `IMPORT` |
| Оценка суммы (Estimated amount) | Потенциальная выручка сделки в валюте организации; неизвестная сумма — пусто, не ноль | `NUMERIC(14,2)`, уверенность `NUMERIC(4,3)` |
| Риск (Risk signal) | Сигнал, что сделку можно потерять; не больше одного активного на сделку и тип | важность `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`; активные статусы `OPEN`, `ACKNOWLEDGED`, `ACTED`; закрывающие `RESOLVED`, `FALSE_POSITIVE`, `IGNORED`, `EXPIRED` |
| NO_RESPONSE | Менеджер не ответил на входящее в рабочее время точки | порог точки (45 мин), `CRITICAL` от 90 мин |
| BOOKING_NOT_CONFIRMED | Клиент выразил намерение записаться, подтверждения нет | 30 рабочих минут, всегда `CRITICAL`, нужен доверенный факт AI |
| PROMISE_NOT_FULFILLED | Бизнес пообещал и не выполнил к сроку из текста обещания | срок из фразы («через час», «до 18:00», «завтра») либо 60 мин; `HIGH` |
| CUSTOMER_SILENT_AFTER_PRICE | Клиент молчит после названной цены | 24 рабочих часа `MEDIUM`, через 48 — `HIGH` |
| FOLLOW_UP_CANDIDATE | Клиент колебался, пора напомнить | 24 рабочих часа, `MEDIUM` |
| Источник риска (Source) | Чем подтверждён риск | `RULE` — только правило; `HYBRID` — правило по доверенному факту AI с уверенностью и ссылкой на прогон |
| Отложенная проверка (Scheduled check) | Запись «проверить правило в срок»; хранит только идентификаторы | типы `*_DUE`; статусы `SCHEDULED`, `ENQUEUED`, `CANCELLED` |
| Radar | Сводка и список активных рисков с серверным порядком | важность, намерение записи, потенциал, срок, обнаружение |
| Вердикт (Feedback) | Оценка риска человеком, append-only со снимком риска | `TRUE_POSITIVE`, `FALSE_POSITIVE`; причины `CUSTOMER_ALREADY_ANSWERED`, `CUSTOMER_ALREADY_BOOKED`, `CUSTOMER_REJECTED`, `NOT_A_LEAD`, `WRONG_INTERPRETATION`, `OTHER` |
| Точность (Precision) | Доля верных срабатываний по типу риска за окно обнаружения | `TP / (TP + FP)`; надёжна при покрытии вердиктами ≥ 0,5 |

## Реакция и деньги

| Термин | Что это | Значения и правила |
|---|---|---|
| Рекомендация (Recommendation) | Шаблонная подсказка по типу риска; создаётся сервером без AI | одна на риск, источник `TEMPLATE` |
| Действие (Action) | Неизменяемая запись реакции менеджера на риск; первое действие переводит риск в `ACTED` | `OPEN_CONVERSATION`, `COPY_REPLY`, `MARK_CONTACTED`, `CALL`, `SEND_MESSAGE`, `OTHER` |
| Исход (Outcome) | Неизменяемая запись результата по сделке; исправление — новой записью | `RESPONDED`, `THINKING`, `BOOKED`, `PAID`, `LOST`, `NOT_A_LEAD` |
| Событие выручки (Revenue event) | Подтверждённая пользователем сумма по сделке | статус `CONFIRMED`, источник `USER_CONFIRMED`, сумма строго положительная |
| Атрибуция (Revenue attribution) | Как выручка связана с работой системы; одна на событие | `RECOVERED` (риск + действие + исход той же сделки, не старше 30 дней; одна на сделку), `ORGANIC`, `UNKNOWN` |
| Idempotency-Key | Заголовок команд, создающих факты; точный повтор возвращает прежний ответ | до 255 символов; другое содержимое с тем же ключом — `409` |
| Аудит (Audit log) | Append-only след критических действий участников и входов | `audit_log`, `auth_audit_log`, `admin_audit_log` |

## Уведомления

| Термин | Что это | Значения и правила |
|---|---|---|
| Уведомление (Notification) | Логический факт «надо сообщить получателю», с персональным ключом дедупликации | виды `RISK_OPENED`, `RISK_DIGEST`, `RISK_ESCALATED` |
| Доставка (Delivery) | Отдельная попытка передать уведомление по каналу; строка на попытку | каналы `TELEGRAM`, `IN_APP`; статусы `PENDING`, `PROCESSING`, `RETRY`, `SUCCEEDED`, `DEAD`; до 5 попыток |
| Политика получателя (Preference) | Личные настройки по типу риска | режимы `IMMEDIATE`, `DIGEST`, `DISABLED`; порог важности; флаги каналов; тихие часы; время сводки |
| Тихие часы (Quiet hours) | Интервал, когда немедленные уведомления откладываются в сводку | по умолчанию 22:00–08:00, выключены; допускается переход через полночь |
| Сводка (Digest) | Одно сообщение с накопленными рисками получателя в назначенный слот | до 15 строк, только активные риски, без кнопок |
| Эскалация (Escalation) | Уведомление владельцу о риске, который никто не принял в работу | флаг конфигурации, через 30 мин, для `HIGH` и выше |
| Привязка Telegram (Telegram link) | Связь участника с личным чатом бота через одноразовый код | код живёт 15 мин, хранится хешем; `/start` только из личного чата |
| Кнопки (Callbacks) | Действия из уведомления в Telegram | `OPEN_RISK`, `ACKNOWLEDGE`, `SNOOZE`; идемпотентны по идентификатору callback |

## AI-контур

| Термин | Что это | Значения и правила |
|---|---|---|
| Домашний узел (AI node) | GPU-машина с llama.cpp и агентом, забирающая задания по pull-модели | статусы `READY`, `OFFLINE`, `REVOKED`; один слот |
| Допуск узла (Node tenant) | Явный список организаций, задания которых узел может брать | таблица `ai_node_tenants` |
| AI-задание (AI job) | Заявка на анализ переписки; не больше одного ожидающего на переписку | статусы `PENDING`, `LEASED`, `RUNNING`, `SUCCEEDED`, `RETRY`, `DEAD`; дебаунс 60 с |
| Прогон (AI run) | Конкретная попытка выполнения задания узлом | статусы `RUNNING`, `SUCCEEDED`, `FAILED` |
| Статус применения (Application status) | Что стало с результатом прогона | `PENDING`, `APPLIED`, `STALE` (переписка изменилась), `REJECTED` (невалидный) |
| Свежесть (Freshness) | Совпадение ревизии переписки и последнего проанализированного сообщения при завершении прогона | проверяется дважды: до и внутри транзакции |
| Семантический факт (Semantic fact) | Вывод модели с уверенностью и доказательствами-сообщениями | `BOOKING_INTENT`, `BUSINESS_COMMITMENT`, `PRICE_MENTIONED`, `FOLLOW_UP_CANDIDATE` |
| Полоса доверия (Confidence band) | Как сервер трактует уверенность | ≥ 0,85 — доверенный (`trusted`), 0,65…0,849 — наблюдение, ниже — отбрасывается |
| Контракт результата | Строгая JSON-схема ответа модели | `analyze-conversation.v1`, резюме ≤ 2000 символов |
| Инструкция (Prompt) | Версионированный запрос к модели из последних 20 сообщений и справки об организации | `analyze-conversation.prompt.v5`, ≤ 12 000 символов |
| Модель | Зафиксированный артефакт с манифестом и порогами качества | `lidradar-main-v1`, `Qwen3-8B-Q4_K_M`, статус `FROZEN` |
| Аренда задания (Lease) | Право узла на задание на ограниченное время | 120 с, продлевается heartbeat, потолок 15 мин |

## Фоновая обработка

| Термин | Что это | Значения и правила |
|---|---|---|
| Outbox | Журнал событий, записываемых в одной транзакции с изменением; доставка как минимум один раз | статусы `PENDING`, `PROCESSING`, `PUBLISHED`, `RETRY`, `DEAD` |
| Событие (Event) | Версионированное сообщение между модулями | `conversation.changed.v1`, `opportunity.created.v1`, `opportunity.stage_changed.v1`, `risk.opened.v1`, `ai.analysis.applied.v1`, `connector.raw-event.received.v1` |
| Задание (Job) | Единица фоновой работы с типом, ключом дедупликации, приоритетом и попытками | статусы `PENDING`, `PROCESSING`, `RETRY`, `SUCCEEDED`, `DEAD` |
| Аренда (Lease) | Владение элементом очереди на 30 с; павший процесс освобождает работу по сроку | владелец — идентификатор запуска процесса |
| Повтор (Retry) | Расписание повторных попыток | 5 с, 30 с, 2 мин, 10 мин; всего 5 попыток |
| Мёртвый элемент (Dead letter) | Событие, задание, доставка или AI-задание, исчерпавшие попытки | статус `DEAD`; администратор делает `retry`/`replay` или `discard` |
| Ключ дедупликации (Dedup key) | Логическая идентичность операции, защищающая от повторов | уникален в паре с типом и организацией, не истекает |
| Планировщик (Scheduler) | Процесс, переводящий просроченные проверки в задания | пачками по 100, `available_at = due_at` |
| Сигнал инвалидации (SSE) | Короткое сообщение «перечитай», без бизнес-данных | `risk.changed`, `risk.acknowledged`, `risk.resolved`, `risk.false_positive` |
| Worker | Процесс, крутящий диспетчер outbox, обработчик заданий и доставку уведомлений | одна горутина, пачка 1, пауза 500 мс |

## Платформа и эксплуатация

| Термин | Что это | Значения и правила |
|---|---|---|
| RLS (Row Level Security) | Построчная изоляция организаций в PostgreSQL; без контекста организации запрос видит ноль строк | роли `lidradar_app`, `lidradar_worker`, `lidradar_platform` |
| Платформенная роль | Роль базы, обходящая политики для очередей, узла и админки | `lidradar_platform` |
| Миграция | Встроенный SQL-файл с контрольной суммой; только вперёд | 21 миграция, последняя `000021_auth_audit` |
| Готовность (Readiness) | Ответ `/health/ready`: база доступна и журнал миграций совпал со сборкой | иначе `503` |
| Корреляция (Correlation) | Идентификаторы запроса и трассы в логах и ответах | `X-Request-ID`, `traceId` в конверте ошибки |
| Ограничение частоты (Rate limit) | Предел запросов по адресу для маршрутов без сессии | вход 120/мин, вебхуки 1200/мин, API узла 600/мин; вход по учётной записи 5 неудач за 15 мин |
| Панель администратора | Read-модели очередей, каналов, узлов и трасс без содержимого переписок | `/api/v1/admin/*` |
| Нагрузочное испытание | Тест с тегом `load` на наборе 100 × 500 × 10 | пороги: API p95 < 300 мс, вебхук p95 < 200 мс, риск < 10 с |
| ADR | Запись архитектурного решения; изменение границ системы только через принятый ADR | 43 записи, индекс в разделе 13 |
