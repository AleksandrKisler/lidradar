# Производные представления и локальная упаковка

Редакция 2026-10-06. Канон — документы вне `docs/notion/` согласно
[политике сопровождения](../engineering/DOCS_GOVERNANCE.md). Четырнадцать
Markdown-представлений этого каталога генерируются из `docs/backend/` и
`docs/adr/README.md`. Их заголовок содержит ссылку на источник и SHA-256.
Правки вносятся в источник; обратного ручного зеркалирования нет.

## Сборка

Достаточно стандартного Python 3.10+; matplotlib и сетевой доступ не нужны.

```bash
python3 -m unittest discover -s docs/notion -p test_build.py
python3 docs/notion/build.py
python3 docs/notion/build.py --check
```

`--check` не меняет файлы и завершается ошибкой при устаревшем представлении
или архиве. CI сначала собирает пакет, затем проверяет повторяемость и zero diff
относительно сохранённых производных Markdown.

В `runtime/docs-package/` создаются:

- `MANIFEST.json`: путь, роль, размер и SHA-256 каждого включённого материала;
- `BUILD_REPORT.json`: фактические числа проверенных страниц, ссылок и anchors;
- `handover.zip`: полный переносимый комплект с относительными путями;
- `batch-NN.zip`: части того же комплекта, максимум 90 исходных файлов в части,
  плюс полный manifest. Это локальное разбиение, не заявленный лимит Notion.

Полнота локальных ссылок проверяется для полного комплекта. Отдельные части
могут ссылаться друг на друга и не считаются самостоятельными пакетами импорта.
Размеры и количество материалов берутся из текущего отчёта, не из старой
редакции H-20. Сборка проверяет вложения на LFS pointers. Архивы имеют фиксированные
метаданные и сортировку; повторная сборка с тем же Python/zlib даёт те же байты.
Неизвестные ссылки, отсутствующие anchors и незакрытые fences прерывают сборку.

`docs/audit/legacy/2026-09-18-backend-notion.zip` и PNG в `images/` — история.
Старые графики не пересчитываются и не подтверждают текущую ёмкость системы.
Старый HTML `_mermaid-check.html` — вспомогательная страница; успешная локальная
сборка не означает, что Mermaid проверен в текущем Notion.

## Приёмка переноса в Notion

В этом цикле импорт не выполнялся. Перед реальным переносом нужны тестовое
пространство, согласованный набор страниц и доступов, карта source path → stable
page ID, проверка ссылок/anchors/таблиц/Mermaid/вложений и обратного экспорта.
Только после этого можно отмечать RG-DOCS-NOTION выполненным.

Повторный импорт с удалением старых страниц не является способом синхронизации.
Обновление существующего пространства должно использовать стабильные page IDs
и сохранять разрешения и историю. Пакет локальной сборки сам по себе не даёт
разрешения публиковать документы или менять доступ.
