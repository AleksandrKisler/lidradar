# Издание документации для Notion

Этот каталог — версия технической документации серверной части LidRadar,
подготовленная для импорта в Notion: страницы Markdown с Mermaid-схемами,
таблицами, графиками и глоссарием. Источник истины остаётся в
`docs/backend/` (для инженеров, с путями к коду); здесь — то же содержание,
собранное так, чтобы корректно перенестись в Notion и читаться командой без
доступа к репозиторию.

## Состав

| Файл | Страница Notion |
|---|---|
| `LidRadar Backend.md` | корневая страница: карта документации, схема системы, ключевые числа |
| `01 Обзор системы.md` … `13 Архитектурные решения ADR.md` | тринадцать разделов, порядок задан номерами; в именах файлов нет скобок и спецсимволов |
| `images/*.png` | графики, на которые ссылаются страницы |
| `build.py` | сборка: рисует графики, проверяет ссылки, собирает zip |
| `_mermaid-check.html` | страница проверки схем (в архив не попадает, см. ниже) |
| `lidradar-backend-notion.zip` | готовый пакет для импорта (собирается `build.py`, в git не хранится) |

## Как импортировать

1. Собрать пакет (нужен Python 3 и matplotlib; см. ниже) или взять готовый
   `lidradar-backend-notion.zip`.
2. В Notion: **Settings & members → Import → Text & Markdown** (или на любой
   странице «⋯ → Import → Text & Markdown») и выбрать zip целиком. Импорт
   всего архива одним действием важен: относительные ссылки между страницами
   превращаются в ссылки Notion, а картинки из `images/` загружаются в
   рабочее пространство.
3. Notion создаст по странице на файл. Корневая страница — `LidRadar Backend`;
   остальные разделы удобно перетащить внутрь неё как подстраницы (порядок
   по номерам).
4. Схемы — блоки кода с языком **Mermaid**. Notion рендерит их сам; если блок
   показан как текст, переключить вид блока на **Preview** или **Split** в
   правом верхнем углу блока.
5. Таблицы импортируются как простые таблицы Notion; при желании любую из них
   можно превратить в базу данных («Turn into → Database»), например
   глоссарий или каталог конечных точек.

## Что учтено при подготовке

- Заголовки не глубже третьего уровня (Notion сводит более глубокие к H3).
- Ячейки таблиц однострочные, без вложенной разметки, кроме `кода`.
- Нет HTML, сносок, определений и колаутов — их Notion из Markdown не
  переносит. Важные замечания оформлены цитатами (`>`), которые Notion
  показывает как блок цитаты.
- Все схемы — Mermaid (`flowchart`, `sequenceDiagram`, `stateDiagram-v2`,
  `erDiagram`), без экспериментальных типов; синтаксис проверен рендером
  Mermaid 11.
- Графики — PNG в `images/`, рядом всегда есть таблица с теми же числами.
- Ссылки между страницами относительные, с `%20` вместо пробелов.

## Как пересобрать

```bash
python3 -m venv .venv && .venv/bin/pip install matplotlib
.venv/bin/python docs/notion/build.py
```

Скрипт перерисует графики в `docs/notion/images/`, проверит, что все
относительные ссылки и картинки существуют, и соберёт
`docs/notion/lidradar-backend-notion.zip`. Правки содержания делаются в
Markdown здесь и, если они касаются фактов о коде, зеркалятся в
`docs/backend/`.

## Как проверить схемы после правок

Страница `_mermaid-check.html` загружает все страницы, извлекает блоки
Mermaid и рендерит их той же библиотекой, что использует Notion. Нужен любой
статический сервер из каталога `docs/notion`, например:

```bash
python3 -m http.server 8765 --directory docs/notion
```

Затем открыть `http://localhost:8765/_mermaid-check.html`: заголовок покажет
число блоков и ошибок, каждый упавший блок выведен с текстом ошибки и
исходником. При последней сборке — 40 блоков, ошибок нет.

## Актуальность

Издание собрано 3 сентября 2026 года по состоянию кода после этапа 25 и
разрешения расхождений (последняя миграция `000021_auth_audit`, ADR по 0043).
При изменениях в коде сначала обновляется `docs/backend/`, затем это издание
и пересобирается zip; в Notion повторный импорт создаёт новые страницы,
старые удаляются вручную.
