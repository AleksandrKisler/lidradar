# 0043: Пороги правил риска в бизнес-времени без таблицы конфигурации

- Status: Accepted
- Date: 2026-09-03
- Baseline: Tasks.md v1.1, §29–§33, §35; заменяет ADR 0035

## Контекст

ADR 0035 предлагал хранить единицу порога вместе со значением в таблице
`risk_policy_configs`, создаваемой «этапом 20», и оставлял открытым вопрос
владельца продукта: считать ли пороги R2 (`CUSTOMER_SILENT_AFTER_PRICE`) и
R5 (`FOLLOW_UP_CANDIDATE`) в календарном или бизнес-времени. Этап 20 занял
политика уведомлений, таблица не появилась, а этапы 16–19 реализовали все
пять правил с порогами-константами в коде и единым способом расчёта —
бизнес-временем точки (`domain.BusinessHours`). Сегодня документ в статусе
`Proposed` описывает несуществующую таблицу, а код содержит решение, не
закреплённое ADR.

Фактическое состояние:

| Правило | Порог | Где задан |
|---|---|---|
| `NO_RESPONSE` | порог ответа точки, по умолчанию 45 мин; `CRITICAL` от 90 мин | `locations.response_threshold_minutes`, константа эскалации в коде |
| `BOOKING_NOT_CONFIRMED` | 30 мин после доверенного намерения записи | константа `BookingConfirmationThreshold` |
| `PROMISE_NOT_FULFILLED` | срок из текста обещания либо 60 мин | парсер `promised_time.go`, константа `PromiseFallbackThreshold` |
| `CUSTOMER_SILENT_AFTER_PRICE` | 24 ч, эскалация 48 ч | константы `PriceSilenceThreshold`, `PriceSilenceEscalation` |
| `FOLLOW_UP_CANDIDATE` | 24 ч | константа `FollowUpDelay` |

Все значения применяются через `AddBusinessTime`/`ElapsedBusinessTime`, то
есть единица порога — бизнес-время — одна для всех правил и не выводится из
типа риска: она закреплена самим механизмом расчёта.

## Решение

1. **Единица порога — бизнес-время точки** для всех пяти правил. Она
   зафиксирована в домене (`domain.BusinessHours`, версии политик
   `*/v1`), а не в данных; смена единицы для отдельного правила — новая
   версия политики через ADR, а не правка строки конфигурации.
2. **Пороги остаются константами кода**, кроме порога ответа `NO_RESPONSE`,
   который уже настраивается на точку (`locations.response_threshold_minutes`,
   1…1440 минут, по умолчанию 45). Это единственный порог, для которого
   есть измеренная потребность в настройке (разное время ответа у разных
   бизнесов).
3. **Таблица `risk_policy_configs` не создаётся** до появления измеренной
   потребности: жалобы пилотных организаций на конкретный порог R2–R5 или
   доля ложных срабатываний по типу (`GET /api/v1/risks/precision`) ниже
   допустимой при покрытии вердиктами ≥ 0,5. Тогда таблица вводится в виде,
   описанном в ADR 0035 (значение + единица + эскалация, одна строка на
   организацию и тип), а константы кода становятся значениями по умолчанию.
4. **Открытый вопрос R2/R5** (календарные сутки против бизнес-времени)
   считается решённым в пользу бизнес-времени на период пилота: при
   девятичасовом дне 24 бизнес-часа ≈ 2,7 календарных суток, что даёт менее
   назойливые напоминания; пересмотр — по метрике точности и обратной
   связи пилота.

## Последствия

- ADR 0035 помечен как заменённый; описанный в нём DDL сохраняется как
  готовый план для момента, когда потребность будет измерена.
- Документация (`docs/backend/03-modules.md`, `07-ai.md`) описывает пороги
  как константы бизнес-времени; тесты правил (`domain/*_test.go`) остаются
  единственным местом, где значения закреплены численно.
- Изменение любого порога сейчас — изменение кода с новой версией политики
  и ADR, что осознанно дороже правки строки, но исключает расхождение между
  организациями до появления инструмента настройки.

## Рассмотренные варианты

- **Создать `risk_policy_configs` сейчас.** Пять правил читают пороги из
  базы, появляется административный интерфейс и миграция данных; без
  измеренной потребности это накладные расходы и второй источник истины
  для значений, которые никто ещё не просил менять. Отклонено до пилота.
- **Оставить ADR 0035 в статусе `Proposed`.** Документ описывает таблицу,
  привязанную к прошедшему этапу; расхождение с кодом сохраняется.
  Отклонено.
- **Календарное время для R2/R5.** Меняет поведение без данных пилота;
  отклонено до измерений.
