# 0035: Явная единица порога риска

- Status: Proposed
- Date: 2026-09-02
- Baseline: Tasks.md v1.1, ЭТАП R (LR-BE-RM-014)

## Контекст

Пороги правил заданы в минутах, но документы не говорят, бизнес-минуты это
или календарные. Для R1, R3 и R4 канон — бизнес-время (§29, §31, §32). Для R2
и R5 §30 и §33 задают бизнес-часы, однако при девятичасовом рабочем дне
«24 бизнес-часа» — это около 2,7 календарных суток; для риска «клиент молчит»
такое ожидание требует явного продуктового решения.

Сейчас пороги R1 и R3 живут в коде и в `locations.response_threshold_minutes`;
таблица `risk_policy_configs` ещё не создана.

## Решение

Единица порога хранится вместе со значением и никогда не выводится из типа
риска. Финальный DDL `risk_policy_configs` (создаётся этапом 20):

```sql
threshold_value  INTEGER NOT NULL CHECK (threshold_value > 0),
threshold_unit   TEXT NOT NULL CHECK (threshold_unit IN ('BUSINESS_MINUTES', 'CALENDAR_MINUTES')),
escalation_value INTEGER CHECK (escalation_value IS NULL OR escalation_value > threshold_value),
CONSTRAINT risk_policy_configs_one_per_type_and_tenant
    UNIQUE NULLS NOT DISTINCT (tenant_id, risk_type)
```

Значения по умолчанию: R1 — 45 `BUSINESS_MINUTES`; R3 — 30 `BUSINESS_MINUTES`;
R4 — 60 `BUSINESS_MINUTES`; R2 — 1440 с эскалацией 2880; R5 — 2880.
Единица для R2 и R5 — **открытый вопрос владельца продукта**: либо
`CALENDAR_MINUTES` (ровно сутки и двое), либо бизнес-время. До решения
поведение по умолчанию не меняется: расчёт ведётся в бизнес-времени.

## Рассмотренные варианты

Отклонены: вывод единицы из типа риска в коде (скрытое правило, которое
ломается при первом же изменении) и отдельные столбцы под каждую единицу
(две колонки с взаимоисключающим NULL сложнее, чем пара значение + единица).

## Последствия

Каждый расчёт порога читает единицу из строки конфигурации. Переход R2/R5 на
календарное время меняет только данные, а не код правил.

## Перенос и откат

Таблица создаётся форвардной миграцией этапа 20 сразу в финальном виде;
существующие пороги R1 и R3 переносятся из кода и `locations` с единицей
`BUSINESS_MINUTES`. Откат к порогам в коде возможен без потери данных.
