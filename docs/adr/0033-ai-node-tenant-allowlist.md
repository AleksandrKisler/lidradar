# 0033: Ограничивать AI-узлы явным списком организаций

- Status: Accepted
- Date: 2026-09-02

## Контекст

AI-задание содержит текст переписки. Ранее любой удостоверенный узел с нужной
версией модели мог захватить задание любой организации, поэтому машинная
аутентификация не обеспечивала изоляцию данных.

## Решение

Хранить разрешительный список пар `AI-узел — организация` в PostgreSQL.
Регистрация узла требует исходную организацию; расширение выполняется только
локальной административной командой. Запрос захвата фильтруется по списку до
возврата инструкции. Составные внешние ключи защищают аренды и запуски на уровне
базы.

## Рассмотренные варианты

Отклонены глобальное доверие любому узлу, передача организации только в
настройках агента и проверка после выбора задания. Эти варианты либо допускают
подмену, либо успевают прочитать чужой текст до отказа.

## Последствия

Узел без назначения безопасно простаивает. Один узел может обслуживать несколько
организаций только после отдельных явных назначений. Смена секрета сохраняет
назначения, а отзыв узла запрещает все запросы.

## Перенос и откат

Миграция восстанавливает пары из исторических запусков и действующих аренд,
чтобы сохранить ссылочную целостность. Узлы без доказанной исторической связи
остаются без доступа до команды `allow-tenant`. Откат, возвращающий глобальную
выдачу инструкций, запрещён; сначала нужен равноценный внешний посредник с
проверкой организации.
