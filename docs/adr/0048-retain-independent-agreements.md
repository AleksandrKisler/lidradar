# 0048: Сохранение независимых незавершённых ожиданий

- Status: Accepted
- Date: 2026-10-09
- Approval: владелец проекта явно поручил сначала исправить пропуски намерений на текущей модели, затем вытеснение незавершённых ожиданий.
- Scope: уточнение доменной политики ADR 0047; модульные границы, PostgreSQL, публичный AI-контракт v2 и один активный Risk каждого типа сохраняются.

## Решение

Свежий проверенный результат анализа обновляет накопительную производную
проекцию договорённостей по `(kind, triggerMessageId)`. Пропуск прежнего
ожидания в ответе модели не означает выполнения. Ранее доверенное ожидание
сохраняет источник AI-run; слабое наблюдение не может стереть сильное или
закрыть его. Доказательства перенесённого наблюдения сверяются с каноническими
сообщениями и исходным контекстом: изменение/удаление лишает его доверенности.
Завершение требует доказательства для того же основания; завершённое
ожидание не возвращается в PENDING по повторному анализу старого сообщения.
Продолжение одной записи предложением времени/согласованным переносом
сохраняет прежнюю семантику смены ожидаемой стороны, но не завершает
независимое препятствие оплате или обещание бизнеса.

Правила R4 и UNFINISHED_AGREEMENT проверяют все подходящие ожидания. При
отсутствии активного риска выбирается ближайший срок, а не последнее
сообщение. Действующее незавершённое основание сохраняется до его собственного
завершения; более новый вопрос не сдвигает срок и не переписывает основание.
Специализированное правило исключает только покрытое им ожидание. После
завершения текущего основания контроль продолжается по оставшимся.

Карточка остаётся агрегатом риска одного типа; пока есть просроченное
ожидание, она активна. При переходе к следующему ожиданию сохраняется
идентичность и подтверждение просмотра агрегата; причина и доказательства
обновляются. Ручное закрытие подавляет повтор этого сообщения-основания,
но не скрывает другое независимое ожидание. Закрытая сделка не переоткрывается. Новая сделка той же беседы не наследует
ожидания, возникшие до последнего закрытия предыдущей сделки.

## Проверки и пределы

Синтетические проверки: два разных ожидания; несколько обещаний; новый
будущий срок при старом просроченном; выполнение одного; пропуск основания
моделью; слабый/устаревший результат; редактирование/удаление доказательств;
закрытое основание; повторная доставка; изоляция организаций. Реальная
Telegram-беседа и вручную закрытый пользователем риск не изменяются.
Не добавляется несколько карточек одного типа или неограниченный контекст
модели. Неоднозначная связь ответа с ожиданием не считается доказанным
выполнением.
