# 0032: Ограничивать попытки аутентификации через PostgreSQL

- Status: Accepted
- Date: 2026-09-02

## Контекст

Публичные маршруты регистрации, входа и обновления сеанса выполняют дорогую
проверку пароля и ранее не имели общей защиты от перебора. Внутрипроцессный
счётчик можно обойти переключением между экземплярами API или перезапуском.

## Решение

Атомарно расходовать ограниченные временные окна в PostgreSQL отдельно для
сетевого адреса и нормализованной учётной записи. Хранить только SHA-256
отпечатки субъектов. Возвращать единый ответ 429 с `Retry-After`, не раскрывая
существование пользователя. Успешный вход сбрасывает только счётчик учётной
записи.

## Рассмотренные варианты

Отклонены локальная память процесса, блокировка поля в таблице пользователей и
доверие произвольному `X-Forwarded-For`. Пограничное ограничение полезно как
дополнительный слой, но не заменяет правило приложения.

## Последствия

Защита переживает перезапуск и работает одинаково для нескольких экземпляров.
PostgreSQL получает небольшой объём короткоживущих счётчиков. Общие адреса NAT
могут временно ограничить несколько пользователей; значения подлежат настройке
по эксплуатационным измерениям, но не должны отключаться.

## Перенос и откат

Миграция создаёт отдельную таблицу без изменения пользователей и сеансов.
Откат приложения требует сначала оставить эквивалентное ограничение на
доверенном пограничном узле; простой отказ от защиты недопустим.
