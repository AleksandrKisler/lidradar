# План проверки этапов 1–7

Дата проверки: 25 августа 2026 года.

## Цель

Подтвердить не только успешный сценарий, но и сохранность данных при повторах,
сбоях, параллельной работе и заведомо недобросовестном вводе. Проверка не
обращается к реальному Telegram и локальной модели AI: для этапа 7 достаточно
локального `GENERIC_WEBHOOK`, PostgreSQL и детерминированных правил.

## Матрица покрытия

| Область | Что проверяется | Уровень |
|---|---|---|
| Этап 1 | живучесть, готовность PostgreSQL, регистрация, вход, выход, закрытый сеанс | HTTP + PostgreSQL |
| Этап 2 | организация, точка, права OWNER/MANAGER, изоляция организаций | HTTP + PostgreSQL |
| Этап 3 | каталог услуг, точные деньги, `NULL` вместо выдуманной цены | домен + HTTP + PostgreSQL |
| Этап 4 | проверка подписи, сохранение до обработки, дедупликация, предел 1 МиБ | HTTP + PostgreSQL |
| Этап 5 | Contact, Conversation, Message, edit/delete, revision, повторы | сквозной сценарий |
| Этап 6 | аренда, повтор, DEAD, `SKIP LOCKED`, падение после claim, outbox | модуль + PostgreSQL |
| Этап 7 | Opportunity, автоматический кандидат, этапы, история, одна активная | домен + HTTP + PostgreSQL |

## Недобросовестный ввод

Обязательные случаи:

- несколько JSON-значений в одном теле;
- неизвестные поля и неверные типы;
- неверный UTF-8 и `U+0000`;
- тело API больше 64 КиБ и webhook больше 1 МиБ;
- SQL-подобные строки в tenant, пути, этапе и сообщении;
- неподписанный webhook;
- чужие tenant и идентификаторы;
- недоверенный `Origin` и опасный `X-Request-ID`;
- некоммерческое, пустое и двусмысленное сообщение;
- случайные байтовые последовательности для общего декодера JSON.

Критерий успеха: предсказуемый ответ `4xx` либо безопасное сохранение
ошибочного RawEvent; паника, `5xx`, утечка внутренней ошибки и частичная
бизнес-запись запрещены.

## Сбои и параллельность

- ошибка записи outbox откатывает Contact, Conversation и Message;
- падение отдельного процесса после захвата задания не теряет работу;
- просроченная аренда позволяет другому обработчику закончить задание;
- повтор побочного эффекта не создаёт вторую запись;
- конкурентные кандидаты создают одну активную Opportunity и одну начальную
  запись истории;
- одинаковые конкурентные переходы добавляют одну запись истории;
- прямое изменение или удаление истории запрещено PostgreSQL;
- отменённый контекст и недоступность зависимости возвращаются как ошибки, а
  не подтверждаются как успех.

## Нагрузка

Выделенный набор с меткой сборки `load` проверяет:

```bash
go test -tags=load -v ./backend/internal/integration \
  ./backend/internal/jobs/infrastructure -run '^TestLoad'
```

Набор создаёт 150 параллельных webhook, 120 конкурентных коммерческих
кандидатов и 300 заданий для 12 обработчиков. Он проверяет полноту записей и
отсутствие повторов, а времена выводит как местную исходную точку. Это не
заменяет длительный пилотный тест производительности этапа 15.
