Комплект описывает серверную часть такой, какая она есть в коде сейчас, без
привязки к этапам разработки. История этапов и аудит задач остаются в
[`../../DONE.md`](../../DONE.md); нормативный контракт поведения — в
[`../spec/BACKEND_SPEC.md`](../spec/BACKEND_SPEC.md); архитектурные решения — в
[`../adr/`](../adr/README.md). Если этот комплект расходится с кодом, прав код,
а документ подлежит правке в той же поставке.

## Система одним абзацем

LidRadar принимает сообщения клиентов из каналов (Telegram Connected Business
Bot, универсальный вебхук, импорт), хранит их как канонические переписки,
распознаёт коммерческие возможности по каталогу услуг организации и
детерминированными правилами находит риски потери сделки: нет ответа
менеджера, не подтверждена запись, не выполнено обещание, клиент замолчал
после цены, пора напомнить. Риски попадают в Radar и в уведомления владельцу и
менеджерам с учётом личной политики (немедленно, сводкой, тихие часы), к
каждому риску есть шаблонная рекомендация, зафиксированные действия и исходы,
а подтверждённая выручка атрибутируется к цепочке «риск → действие → исход».
Асинхронный AI на домашнем GPU-узле добавляет только семантические факты
(намерение записи, обещания, цена) для тех же детерминированных правил и не
меняет состояние сделки сам. Всё это — один Go-монолит из процессов `api`,
`worker`, `scheduler`, `ai-agent` и `migrate` поверх PostgreSQL с построчной
изоляцией организаций.
